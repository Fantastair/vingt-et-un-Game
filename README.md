### 一、问题描述

21点纸牌游戏（Blackjack）是一种非常受欢迎的纸牌游戏，起源于1700年左右的法国赌场，当时的游戏名为 "vingt-et-un”（法文中 21 之意）。该游戏的目标是通过手中的牌点数接近或达到21点，但不能超过21点。玩家和庄家各自从一副52张牌（不包括大小王）中抽牌，最终点数更接近21点的玩家获胜。

1. ***游戏规则***
   - **牌面点数**： 2 到 10 的牌面值等于其点数，J、Q、K 每张为 10 点，A 可记为 1 点或 11 点。若总点数超过 21 点，则称为 “爆牌”。
   - **发牌规则**：每位玩家和庄家各自发两张牌，庄家的一张牌面朝上（明牌），一张牌面朝下（暗牌）。若庄家的第一张牌是A或10，则庄家需检查是否构成21点，并在所有玩家行动后再决定是否继续抽牌。
2. ***胜负条件***
   - **天生 21 点**：玩家起手拿到 A 和 10 点牌时，形成 "天生 21点”（Blackjack），若庄家没有同样牌型，玩家获胜。
   - **爆牌**：若玩家的点数超过 21 点或庄家点数达到或超过 21 点但玩家未超过，玩家输掉该局。
     **平局**：若玩家和庄家的点数相同，则为平局（push）。

- ### 扑克牌池 `CardPool`

  这个类专门用于管理 `Card` 类，此类不需要实例化，完全使用类的静态函数即可

  实现的相关功能包括洗牌、发牌、剩余牌堆分析（用于辅助电脑决策）等

  ```c++
  /**
   * @brief 游戏卡牌池
   * @details 管理卡牌的发放和回收，辅助电脑决策
   */
  class CardPool
  {
      public:
          static Card *card_list[52];                          // 卡牌列表
          static int next_card;                                // 下一个发放的卡牌
  
          static void Init(void);                              // 初始化卡牌池
          static void Release(void);                           // 释放卡牌池
  
          static void Shuffle(void);                           // 洗牌
          static void SetCardOrder(std::string card_order);    // 设置卡牌顺序
          static Card *GetCard(void);                          // 获取一张卡牌
          static int GetCardIndex(int card_num);               // 获取卡牌索引
          static float GetSafeCardRation(int safe_num);        // 获取安全卡牌几率
  };
  ```

  不需要频繁的创建和销毁卡牌，只需要每一局游戏开始时通过元素交换实现洗牌即可，内部维护一个静态指针数组，存储所有卡牌，同时用一个变量 `next_card` 记录下一张发放的牌。

  关于洗牌，采用的是经典的 **Fisher-Yates 洗牌算法**，也正好符合游戏的情景。从尾部遍历数组并向前随机交换位置，实现顺序打乱

  ```c++
  /**
   * @brief 洗牌
   * @details 洗牌算法使用 Fisher-Yates 洗牌算法
   */
  void CardPool::Shuffle(void)
  {
      for (int i = 51; i > 0; i--)
      {
          int j = MyRandomInt(0, i);
          if (j == i) continue;
          std::swap(card_list[i], card_list[j]);    // 交换卡牌
      }
      next_card = 0;
  }
  ```

  这个算法可以很好的保证每张牌在每个位置出现的概率相等，但这是理论上的，因为在计算机里无法产生真随机数。可以看到上面的函数中我使用了一个自定义的随机数发生函数 `MyRandomInt`，C++ 里随机数的计算依赖于种子，相同的种子将产生相同的随机数，因此每次产生随机数后更换种子是实现随机的关键，在主函数里有这样一行代码：

  ```C++
      srand(static_cast<unsigned int>(time(nullptr)));    // 设置随机数种子
  ```

  这行代码的作用是是使用当前的时间作为种子，但是这样没办法在短时间内产生大量不同的随机数，因此还需要在另一个地方播种：

  ```c++
  /**
   * @brief 随机整数
   * @param min 最小值
   * @param max 最大值
   */
  int MyRandomInt(int min, int max)
  {
      int result = rand();
      srand(result);
      return result % (max - min + 1) + min;
  }
  ```

  我将每次随机数的结果作为种子进行播种，这样在产生一个新的随机数后就能够获得一个新的种子，虽然这样的随机不够理想，但是对于我们的游戏来说足够了。

- ### 玩家 `Player`

  作为一个玩家，需要实现持有一定数量的卡牌，并统计手牌的点数（当然在我们这个程序中还要负责自身信息的显示，这是后话了）

  > ##### 此外还有一个 `Computer` 类，继承自 `Player`，代表电脑控制的庄家，二者的差异主要在图形渲染上，这里不予展示类定义

  ```c++
  /**
   * @brief 游戏玩家类
   */
  class Player : public Ui
  {
      public:
          Ui_Image *head;                                // 玩家头像
          Ui_Text *name;                                 // 玩家名称
          Ui_Image *full_medal;                          // 爆牌图标
          Ui_Image *born_with_21_medal;                  // 天生 21 点图标
          std::list<Card*> hand_cards;                   // 玩家手牌列表
          int num;                                       // 玩家编号
          int show_medal_flag;                           // 图标显示标志，0：不显示，1：显示爆牌图标，2：显示天生 21 点图标
  
          Player(int player_num);
          virtual ~Player();
  
          virtual void render(void);                     // 渲染函数
          virtual void set_topleft(float x, float y);    // 设置玩家位置
          virtual void show_medal(int medal_flag);       // 显示图标
  
          virtual void GetCard(Card *card);              // 玩家获取一张卡牌
          virtual int CalcCardValue(void);               // 计算手牌点数
          virtual int CalcMinCardValue(void);            // 计算手牌最小点数
          virtual void return_cards(void);               // 归还手牌
  };
  ```

  在计算手牌时可以方便的调用 `Card` 的接口获取各张手牌的点数，但是需要考虑到一个特殊的手牌 A，在游戏规则中它既可以是 11 点，又可以是 1 点。首先当然希望自己的点数越大越好（不超过 21 点的前提下），所以 `Card` 的实现中 A 的点数固定为 11，而玩家在统计手牌点数的时候还需要记录 A 的数量，如果手牌点数超出了 21 点，试图将部分 A 按照 1 点计算：

  ```c++
  /**
   * @brief 计算手牌点数
   * @details 当手牌不超过 21 点时，A 为 11 点；否则部分 A 会按照 1 点计算，以尽可能保证手牌点数不超过 21 点
   */
  int Player::CalcCardValue(void)
  {
      int value = 0;                                   // 点数
      int A_count = 0;                                 // A 的数量
  
      for (auto card : hand_cards)                     // 遍历手牌
      {
          if (card->get_letter() == "A") A_count++;    // 统计 A 的数量
          value += card->get_point();                  // 计算点数
      }
      if (value > 21)                                  // 如果点数超过 21 点
      {
          for (int i = 0; i < A_count; i++)            // 将部分 A 按照 1 点计算
          {
              value -= 10;
              if (value <= 21) break;                  // 直到点数不超过 21 点
          }
      }
  
      if (value > 21) show_medal(1);                                    // 如果点数超过 21 点，显示爆牌图标
      else if (value == 21 && hand_cards.size() == 2) show_medal(2);    // 如果点数为 21 点且手牌数量为 2，显示天生 21 点图标
      else show_medal(0);                                               // 否则不显示图标
      return value;
  }
  ```

// 分析胜负
int result_flag;                                       // 结算结果，0 表示平局，1 表示玩家胜利，2 表示庄家胜利
if (points[0] > 21)                                    // 庄家爆牌
{
    result_flag = 0;                                   // 平局
    for (int i = 0; i < GetPlayerNumSetting(); i++)
    {
        if (points[i + 1] <= 21)                       // 有玩家未爆牌
        {
            result_flag = 1;                           // 玩家胜利
            break;
        }
    }
}
else if (points[0] == 21)                              // 庄家达到 21 点
{
    result_flag = 2;                                   // 庄家胜利
    for (int i = 0; i < GetPlayerNumSetting(); i++)
    {
        if (points[i + 1] == 21)                       // 有玩家达到 21 点
        {
            result_flag = 0;                           // 平局
            break;
        }
    }
}
else                                                   // 庄家未爆牌且未达到 21 点
{
    int max_point = 0;                                 // 最大点数
    for (int i = 0; i < GetPlayerNumSetting(); i++)
    {
        if (points[i + 1] > max_point && points[i + 1] <= 21)
        {
            max_point = points[i + 1];
        }
    }

    if (max_point > points[0]) { result_flag = 1; }          // 玩家胜利
    else if (max_point == points[0]) { result_flag = 0; }    // 平局
    else { result_flag = 2; }                                // 庄家胜利

#### 上层交互层

下面我们介绍整个游戏的图形化框架。

我是用的图形库是 **SDL**，这是一个开源的跨平台多媒体开发库，主要用于开发游戏、多媒体应用程序等。它提供了一套简单的API接口，用于处理图形渲染、音频播放、输入设备（如键盘、鼠标、游戏手柄）等。

> ##### 进一步说明：（和本项目的关系不大，纯粹有感而发）
>
> SDL 实际上是一个使用起来相对复杂的图形库，它并没有实现一些交互组件（比如按钮）的设计，甚至窗口渲染的主循环都需要我自己编写，事实上 SDL 的主要功能只有两个：
>
> - 提供绘制图片、填充颜色、渲染文本的画图函数
> - 提供事件接收机制，开发者可以获取鼠标、键盘等外设的一系列操作记录
>
> 也就是说，如果你需要一个按钮，你得先在屏幕上绘制一个矩形，然后接收鼠标点击事件，判断鼠标点击位置是否在矩形内，如果是，则执行对应的自定义函数。
>
> 那么为什么我要使用这样一个复杂的库呢？第一点是因为 SDL 在 python 编程语言中有一个封装库名为 pygame，而我此前对这个库有较多的接触，由于 pygame 就是基于 SDL 提供一系列 python 接口，所以二者逻辑基本相似，对于我来讲几乎没有学习成本。第二点是虽然 SDL 的功能相对底层，但是更少的封装意味着更大的自由，我在 python 端基于 pygame 编写了一个较为完善的图形交互框架，本次在 C++ 端的交互开发其实就是那个框架核心思路的简化实现，并且由于 SDL 相比于 pygame 还要少一层封装，所以我在这次项目的开发中也发现了一些好用的特性实现，也算是不虚此行。

要建立一套基础的图形显示框架，我们需要解决几个问题：

- 哪些元素需要显示？
- 各个元素显示什么内容？
- 各个元素如何将这些内容显示到屏幕上？
- 各个元素显示在屏幕的什么位置？
- 各个元素显示的先后顺序是什么？

来看最底层的一个抽象类 **`Ui`** 的声明：

```c++
/**
 * @brief 显示元素
 */
class Ui
{
    public:
        static UI_LIST_TYPE *ui_list;                   // 显示队列指针
        static void SetUiList(UI_LIST_TYPE *list);      // 设置元素列表

        std::string id;                                 // 元素唯一ID
        void (*clicked)(void);                          // 点击事件函数指针

        Ui(std::string id);
        virtual ~Ui();

        virtual void render(void) = 0;                  // 渲染函数
        virtual void join(UI_LIST_TYPE *list);          // 加入元素列表
        virtual void leave(UI_LIST_TYPE *list);         // 离开元素列表
        virtual void bind_click(void (*func)(void));    // 绑定点击事件函数
        virtual bool collidepoint(float x, float y);    // 碰撞检测函数
};
```

显示队列指针是一个类的静态指针，它指向一个存储 `Ui` 对象的 `list` 链表，可以解决两个问题：显示哪些元素和显示顺序。只要我更改其指向的链表，就可以从一堆元素的显示切换到另一堆元素的显示，通俗来讲就是界面；而链表的遍历顺序就是元素的显示顺序。

```c++
/**
 * @brief 窗口主循环
 */
void Display_Mainloop(void)
{
    while (true)
    {
        auto st_ = SDL_GetTicksNS();    // 获取当前时间戳

        SDL_Event event;
        while (SDL_PollEvent(&event))
        {
            if (event.type == SDL_EVENT_QUIT) { goto end; }        // 用户关闭窗口
            else if (event.type == SDL_EVENT_MOUSE_BUTTON_DOWN)    // 用户鼠标按下
            {
                Handle_MouseButtonDown(event.button.x, event.button.y, event.button.button);
            }
        }

        handle_action();    // 处理玩家行动

        if (update_flag)    // 更新标志为真，表示需要更新界面
        {
            // 填充背景色
            SDL_RenderClear(renderer);
            // 渲染元素
            for (auto &ui : UI_LIST) { if (ui != nullptr) ui->render(); }
            // 更新屏幕
            SDL_RenderPresent(renderer);
            update_flag = false;
        }

        Uint64 elapsed_time_ = SDL_GetTicksNS() - st_;    // 计算帧间隔时间
        if (elapsed_time_ < frame_time_)                // 如果帧间隔时间小于设定的帧时间
        {
            SDL_DelayNS(frame_time_ - elapsed_time_);
        }
    }
    end:;
}
```

时间戳相关的处理是用来控制帧率的，主循环的每一轮循环就是一帧，不仅仅影响到显示刷新速率，还影响到事件处理响应速率，本程序锁定最大60帧。

第一块代码就是处理事件的，从队列中逐个抽取事件并分析（在这个程序中，我只分析了两种事件，关闭窗口事件和鼠标按下事件，事实上 SDL 提供了非常多的事件），可以看到在处理鼠标按下事件时，我重点关注了事件的三个参数：XY坐标和按键代号。

`handle_action` 是自定义的游戏逻辑函数，在前面有提到。

接下来一块代码就是渲染函数，为了节约资源，我使用了一个标志 `update_flag` 来控制是否执行渲染，当其他部分的代码修改了显示的内容时，需要显示地调用 `mark_update()` 接口来标记更新，这样避免了重复绘制相同的内容，结合帧率控制一起作用，使得主循环较多时间是以低资源消耗运行的。

- ##### 游戏对局的存储与导入

  和游戏配置文件一样，这个功能依靠计算机文件系统实现游戏对局的持久化保存。

  具体来说，在开始游戏之前，用户可以选择**从外部文件导入游戏对局**，这场对局的进度可以是发牌后到庄家（电脑控制）行动前的任何一个时刻，可以恢复游戏保存时的状态。另外，在游戏进行到上述任意时刻时，用户也可以选择**导出游戏对局到外部文件**。

  这种对局保存的特性可以为游戏提供更多的发展可能。比如避免了一局游戏开始而无法中途暂停或关闭的场面；或是碰到精彩的对局，可以保存下来并分享给他人，形成残局模式，发展游戏社区生态。

  关于对局存储的实现方式，存在两种方向的构想：

  - 第一种是通过文件**记录当前对局的所有状态**，包括卡牌顺序，各玩家持有手牌等等，在导入的时候还原所有的状态，并继续游戏。

    这种方式的好处是存储的内容仅和当前游戏状态有关，占用空间小，还原速度快。

  - 第二种是**记录游戏的初始状态和后续的所有操作**，还原时快速执行一遍已经进行的游戏进程，通过已有的游戏逻辑代码恢复到记录的状态。

    这种方式的好处是实现简单可靠，缺点是文件占用空间较大，还原速度较慢。

  虽然第一种方法效率更高，但是随着游戏内容的更新或是内部细节的修改，这种方式维护起来愈发的困难，出BUG的风险更高，而另一种方式则通用的多，因为就是运行了一局完整的游戏，更加的稳定。

  综上，本项目最终采用的方式是第二种，这里可以展示一下存储到文件的具体内容：

  action=1
  action=1
  action=2
  action=1

  具体效果在测试环节展示。

  

- ##### 电脑决策机制优化

  由于这个游戏内容本身比较简单，所以电脑决策的机制也没有太复杂，不过这方面的尝试还是很有意义的。

  在游戏里你可以设置两档难度：简单和困难，分别对应了电脑（庄家）的两种要牌策略：

  - 简单

    利用之前编写的随机数发生函数，随机地决定是否要牌。

    由于这种决策机制对场上的情况完全没有考虑，故设定为简单档。

  - 困难

    你也许会注意到在 `Card_Pool` 类的声明中有一个接口 `GetSafeCardRation`，这个函数会返回下一张牌的点数小于传入参数的概率，这就是用于辅助电脑决策提供的一个函数。

    这里的决策机制是根据自身手牌点数和场上已有的牌计算下一张爆牌的可能性，如果爆牌可能性大于 50 %，则停牌，这种决策机制更加科学，考虑到对局因素，故设定为困难档。

  简单的测试可能难以显示出两种策略的差异，不过这会影响对局玩家的心理，也算增加了游戏乐趣。
